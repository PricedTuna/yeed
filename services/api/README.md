# yeed-api

Yeed's REST API: Python 3.13 functions on AWS Lambda behind Amazon API Gateway (HTTP API). It uses [Powertools for AWS Lambda](https://docs.powertools.aws.dev/lambda/python/latest/) for routing and structured logs, [uv](https://docs.astral.sh/uv/) for dependencies and tools, and AWS SAM for building, running locally and deploying (`infrastructure/template.yaml`).

## Setup

```powershell
cd services/api
uv sync
```

`uv sync` reads `.python-version` (3.13), creates `.venv` and installs the exact versions in `uv.lock`. If Python 3.13 is missing, uv downloads it. Prefix commands with `uv run` so they always use this environment, whatever `python` points to on your machine.

## Commands

From `services/api`:

| Command                | What it does                |
| ---------------------- | --------------------------- |
| `uv run pytest`        | Runs the tests.             |
| `uv run ruff check .`  | Lints the code.             |
| `uv run ruff format .` | Formats the code.           |
| `uv run mypy`          | Type-checks in strict mode. |

From the repository root, `pnpm check:api` runs all of them without changing files.

## Running the API locally

Requires Docker Desktop running and AWS SAM CLI. From `infrastructure/`:

```powershell
sam build
sam local start-api --port 3000
```

Or from the repository root: `pnpm dev:api`. Then open <http://localhost:3000/health>.

`sam local` runs each request in a Docker container that emulates Lambda, using the code built in `infrastructure/.aws-sam/`. After changing the code, run `sam build` again.

To invoke one function with a sample event:

```powershell
sam local invoke HealthFunction --event ../services/api/events/get-health.json
```

## Dependencies

```powershell
uv add <package>          # runtime dependency
uv add --dev <package>    # development tool
```

SAM packages the Lambda code from `src/requirements.txt`, which is generated from `uv.lock`. After changing runtime dependencies, regenerate it and commit `pyproject.toml`, `uv.lock` and `src/requirements.txt` together:

```powershell
uv export --format requirements.txt --no-dev --no-emit-project --output-file src/requirements.txt
```

Each new dependency needs a reason in the pull request. Dependencies with native code must provide Linux wheels, because Lambda runs on Amazon Linux.

## Structure

```text
services/api/
├── events/                  Sample Lambda events for `sam local invoke`
├── src/                     Everything in here is deployed to Lambda
│   ├── requirements.txt     Runtime dependencies (generated by uv)
│   └── yeed_api/
│       ├── handlers/        Lambda entry points: one module = one function = one group of routes
│       └── shared/          Router factory and errors used by every handler
└── tests/                   pytest tests, mirroring src/yeed_api
```

Folders are created when the first file needs them: `domain/` (entities and business rules), `services/` (use cases), `repositories/` (PostgreSQL access), `schemas/` (request and response validation) and `config/` (settings).

## Conventions

- **Thin handlers.** A handler reads the request, calls a use case and returns the result. No business rules or SQL in handlers.
- **One function per feature group** (for example `health`, later `auth`, `resources`, `ratings`), not one per route. Each handler module creates its router with `create_app()`.
- **Errors.** Raise `ApiError(status, code, message)` for expected failures; `message` is shown to users. Any other exception becomes a `500 internal_error` response, and its details go only to the logs.
- **Logs.** Powertools `Logger` writes JSON with the request ID. Never log passwords, tokens, whole events or personal data.
- **Types.** mypy in strict mode. `Any` only at the Lambda boundary (raw events and responses).
- **Tests.** Build events with `tests/support.py`. Tests never call AWS.

## API

All responses are JSON with `snake_case` fields. Errors always have this shape:

```json
{
  "error": {
    "code": "not_found",
    "message": "The requested route does not exist."
  }
}
```

| Method | Path      | Authentication | Success response                              |
| ------ | --------- | -------------- | --------------------------------------------- |
| `GET`  | `/health` | None           | `200 {"status": "ok", "service": "yeed-api"}` |

`GET /health` only reports that the API is reachable. It does not use the database or any other service, and it returns nothing sensitive.
